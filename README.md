# Gecko Presence — Signal Deck 0.5.0

A local-first Android Rich Presence controller with an optional Gecko browser module. Android app tracking works directly from the APK. Firefox website tracking uses the XPI that is bundled inside the APK and exported only when the user requests it.

## What changed in 0.5.0

- One primary Android APK. The Gecko extension is bundled in `app/src/main/assets/gpb-extension/` by the suite workflow and can be exported as an unsigned `.xpi` from the app.
- Android app picker is searchable, shows app icons and package names, and saves an explicit allowlist.
- Android foreground detection remains based on `UsageStatsManager`; it reports only the selected foreground package and does not inspect other apps' screens, notifications, or media titles.
- Banking, payment, finance, wallet, investment, authentication, password, health, identity, government, messaging, browser, and other privacy-sensitive categories remain excluded.
- Website access is granted per domain, instead of requesting every HTTP/HTTPS site at once.
- Media titles are extracted only while a media element is playing, paused, or ended. IDLIX metadata extraction prioritizes JSON-LD, then player headings, Open Graph metadata and document title; series/season/episode fields are preserved when available.
- A single Android setting controls whether browser media titles can be forwarded to Discord.
- Hybrid PreMiD API v1 compatibility runtime plus GPB-native adapters; historical IDLIX source is pinned and hash-verified.
- UAM v2 bridge endpoints with v1 backward compatibility.
- Separate Activity Preview, Developer Lab, and Custom Presence Studio in the browser module.
- New high-contrast black/yellow brutalist interface and a new signal emblem.

## Important platform boundaries

- Android app tracking works without Firefox or the XPI.
- Reading an external Firefox/Tor tab requires an extension inside that browser. The APK therefore includes an XPI exporter; it does not secretly read browser tabs.
- Regular Firefox Android requires a Mozilla-signed XPI for normal installation. The app exports an unsigned XPI; upload it as an unlisted add-on to AMO and install the signed download. Temporary/debug installation is a development route, not a permanent production installation.
- Tor Browser support is experimental and must be tested against the exact Tor Browser version. Do not lower Tor security settings to force installation.
- Usage Access gives foreground-app information, not a movie title or song metadata from another application. Those details require an app-owned public integration. This build deliberately does not use Accessibility scraping or Notification Listener access.
- The Discord SDK AAR is not generated by this project. It must be obtained through Discord's official Developer Portal onboarding after approval. App eligibility for a generic presence companion needs confirmation because Discord currently frames the Social SDK primarily as a game integration.

## Build

Use the suite workflow in `.github/workflows/build.yml` after copying it into the repository's `.github/workflows/` folder. It expects the source archive `GeckoPresence-Suite-0.5.0-Source.zip` at the repository root, extracts the actual `GeckoPresenceHost` and `GeckoPresenceBridge` folders, runs extension tests, copies the built extension into APK assets, and builds one APK.

To enable the optional SDK build:

1. Obtain the official `discord_partner_sdk.aar` from Discord's Developer Portal onboarding.
2. Place it at `GeckoPresenceHost/app/libs/discord_partner_sdk.aar` in a private repository or an access-controlled artifact location. Do not publish the SDK binary in a public repository unless its license explicitly permits redistribution.
3. Set the repository variable `DISCORD_APP_ID` to the numeric Application ID from your own Discord application.
4. Run the workflow. If the AAR or Application ID is absent, the workflow intentionally builds a Preview APK with the local bridge and Android app tracking enabled.

The Gradle project leaves `DISCORD_APP_ID` unset by default. Do not add `DISCORD_APP_ID=0` to `gradle.properties`.
